## How to fill this in

1. Copy `notebooks/profiling/dictionary_deped.py` as a starting point and adapt the file list and the documentation parser to the new publisher.
2. The script verifies each file's SHA-256 against the source card before reading anything.
3. Rerunning the script on the same files must produce an identical file.

Adapt the table where the source needs it, and say so in the header:

- **Several files or years:** add a column showing which files or years contain each column, and flag columns whose labels change between them (see `deped_enrollment`).
- **Data covering a subgroup only:** add a fill-rate column for that subgroup (see `deped_facilities`, "Filled (public)").
- **No publisher documentation for a column:** write **Not in the publisher's documentation (undocumented)** in **Description (publisher)**. Never write a description there from guesswork. If the team can say what the column most likely means, write it in **Our interpretation** instead (next section).

## Our interpretation

This column keeps the team's reading of a column separate from the publisher's words, so a reader always knows who said what (D-011). Every entry starts with one label and gives its evidence:

| Label | Use when | Evidence to give |
|---|---|---|
| **[other source]** | Another authoritative document explains it (a law, a department order, the publisher's website) | The document and section, e.g. "Local Government Code, RA 7160, Sec. 451" |
| **[observed]** | The data shows it clearly | The numbers, or the finding ID in `profile.md`, e.g. "82 `Capital` rows, the same as the 82 provinces" |
| **[assumed]** | It is a reasonable reading of the header or the values, but not proven | What it rests on, e.g. "the header says `Old names`" |

Rules:

1. **One label per claim, always with evidence.** An entry can combine labels when it makes several claims, e.g. "[other source] CC = component city (RA 7160, Sec. 451). [observed] All 33 HUCs have a province-level code."
2. **Never copy an interpretation into Description (publisher).** That column is the publisher's words only.
3. **Write it in the script,** next to the publisher's text, so the dictionary stays generated and a rerun reproduces it.
4. **An [assumed] entry the pipeline relies on needs a suspected finding** (S-*n*) in `profile.md`, so it gets tested. When the test confirms it, change the label to [observed] and cite the finding.
5. **Leave it blank** when the publisher's description already says what the column means.
